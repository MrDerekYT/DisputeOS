# Decisions log

| #   | Decision                                                                                                                                                     | Why / follow-up                                                                                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Jest** (already configured) instead of Vitest for unit tests.                                                                                              | Avoid churn; revisit if Vitest-only features are needed.                                                                                                |
| 2   | **One org per user** (`users.org_id`) for Phase 1 instead of a `memberships` table.                                                                          | Simplest correct RLS now. Migrating to `memberships` (multi-org staff, white-label resellers) is planned before Phase 7; tenant tests will be extended. |
| 3   | **Passkeys deferred.** Supabase Auth has no native WebAuthn/passkey login yet. MFA is TOTP via Supabase MFA, enforced in middleware (AAL2 for `/dashboard`). | Add WebAuthn as an MFA factor when Supabase ships it, or via a self-hosted WebAuthn flow.                                                               |
| 4   | **MFA is required for every dashboard user**, not only staff.                                                                                                | Safer default; relaxing for client portal users (Phase 6) needs a role lookup in middleware.                                                            |
| 5   | **Field encryption is app-level AES-256-GCM** with versioned key ids; keys live in Supabase Vault and are injected as env secrets at deploy.                 | Vault/pgsodium is unavailable on plain Postgres (CI). Rotation: set `PII_ENCRYPTION_KEY_ID`/`_PREVIOUS*`.                                               |
| 6   | **i18n via next-intl with a `locale` cookie** (no URL prefix).                                                                                               | Keeps URLs stable for the authenticated app; public marketing pages may adopt prefixed routes later. A test asserts EN/ES key parity.                   |
| 7   | **CSP is per-request with a nonce** in middleware; pages render dynamically.                                                                                 | Strict CSP without `unsafe-inline` scripts. Static marketing pages can be split out later for caching.                                                  |
| 8   | **Sessions:** idle/absolute timeouts are configured in Supabase project settings (`supabase/config.toml` for local).                                         | Supabase enforces them server-side; require Pro plan for inactivity timeout.                                                                            |
| 9   | **RLS suite runs on plain Postgres** with a stub `auth` schema (`supabase/tests/00_auth_stub.sql`).                                                          | Fast, no Docker/Supabase CLI in CI.                                                                                                                     |
| 10  | **Sign-up always creates the signer as `owner` of a new org**; role is never read from user metadata.                                                        | Prevents privilege escalation. Staff/clients are added by owners via the service role (Phase 2/7).                                                      |
| 11  | Phase 1 ships the **existing 12-table schema**; the remaining tables in the spec are added in the phase that needs them.                                     | Avoids unused, untested schema.                                                                                                                         |
| 12 | **Phase 2 parsing is rules-based for text/HTML only.** PDFs/images are vaulted but not parsed until the OCR provider + LLM pipeline (Phase 3/5). | Avoids shipping an unreviewed LLM path; the confidence + review model is already in place for it. |
| 13 | **Virus scanning is not implemented yet** (uploads are type/size-checked by content only). | Needs ClamAV or a scanning API behind a job; tracked in SOC2 checklist. Do not enable client uploads until done. |
| 14 | **Signed URLs / "access reason" prompt** not yet built — no document download UI exists yet. | Will be added with the document viewer; storage RLS already blocks cross-org reads. |
| 15 | Review snippets are masked (digit runs of 5+ → last 4) and stored in `report_imports.parsed` (RLS-protected). Raw report text is never stored in the DB. | Limits PII exposure; originals stay in the private vault. |
